# RepoMirror 镜像同步

`scope: context:repomirror`

## 范围

本上下文只适用于 `RepoMirror/` 在两个本地 Git 仓库之间执行的单向镜像，不扩展为 Git 合并工具、同步盘或远程仓库管理器。

## 规范语言

- **源仓库（SourceRoot）**：当前方向下提供可同步文件集合的仓库。
- **目标仓库（TargetRoot）**：当前方向下接收镜像结果并承担保护规则的仓库。
- **差异条目（DiffEntry）**：一个新增、修改或删除候选文件。
- **保护路径**：`.git`、任意层级 `.gitignore` 或被目标仓库 `git check-ignore` 命中的路径。

## 稳定规则

1. `A_TO_B` 和 `B_TO_A` 只是可选择的单向方向；一次执行只能有一个源端和一个目标端，不执行双向自动合并。
2. 源文件集合通过 Git 的 tracked/untracked 且排除标准忽略项的结果确定；差异内容按文件实际内容比较，不依赖时间戳。
3. `.git` 目录和 `.gitignore` 文件永远不会被复制、删除或覆盖；目标端保护路径不进入可执行同步集合。
4. 常见文本文件只有换行风格差异时不算修改；二进制文件仍按字节严格比较。
5. 目标仓库的未提交和未跟踪状态必须显式展示；不能静默覆盖用户已有改动。
6. 提交和推送只作用于当前目标仓库；空提交信息、非法路径、非 Git 仓库或 Git 命令失败必须显式报错。
7. 不提供 merge、rebase、stash、冲突解决、分支管理或提交历史浏览。
