# GistSync 配置同步

`scope: context:gist-sync`

## 范围

本上下文只适用于 `GistSync/` 将本地配置文件加密后同步到 GitHub Gist，并从快照按条目恢复的流程。

## 通用语言

- **配置集（Profile）**：一组要同步的本地配置文件及其恢复策略；应用始终有至多一个活动配置集。
- **条目（ProfileItem）**：配置集内一项本地文件，带稳定 ID、源路径模板、相对路径和启用状态。
- **快照（Snapshot）**：一次上传产生的、属于一个配置集的加密文件引用集合。
- **清单（Manifest）**：Gist 中的 `sync_manifest.json`，保存配置集和快照元数据。
- **原路径恢复（original）**：按条目源路径恢复。
- **指定根目录恢复（rooted）**：按条目相对路径写入用户提供的根目录。

## 稳定规则

1. 同步内容以“配置集 + 条目 + 快照”组织，云端不保存文件明文。
2. 只有启用且被选择的条目可进入上传；恢复也可按条目选择。
3. 每次上传为配置集新增快照；快照中的每个条目指向独立加密 blob。
4. 没有主密码不能上传或恢复；主密码错误导致恢复失败，不得写入目标文件。
5. 既有目标文件默认不覆盖；必须对该条目显式授权后才能覆盖。恢复前可预检冲突并显示差异。
6. `rooted` 恢复必须有非空根目录；否则请求无效。
7. 每次从云端读取配置集或快照时必须以当前 Gist 清单为准，不能用本机缓存遮蔽其他设备的变更。
8. Token 和主密码由系统凭证库保存；设置 JSON 只保存凭证引用，不能写入明文凭证。
9. 候选主密码在保存前必须经过只读云端快照验证；无法验证时不得静默写入凭证库。

实现边界见 [gist-sync.md](../../architecture/packages/gist-sync.md)。
