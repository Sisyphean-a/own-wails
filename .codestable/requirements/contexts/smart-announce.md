# SmartAnnounce TTS 播报

`scope: context:smart-announce`

## 范围

本上下文只适用于 `SmartAnnounce/` 将中文促销文案生成 MP3 播报并在桌面端试听、循环播放和导出的流程。

## 通用语言

- **播报文案**：用户输入并提交给 TTS 的文本；首尾空白会被规范化。
- **音色**：Minimax 的 `voice_id`；生成请求必须有音色，未主动更改时使用成熟女性音色 `female-chengshu`。
- **生成音频**：TTS 返回并写入本地文件的 MP3 数据。
- **试听数据**：供当前页面 HTML Audio 播放的 Base64 Data URI，不是持久化真源。
- **导出**：通过 Wails 原生保存对话框，把已生成的本地 MP3 复制到用户指定路径。

## 稳定规则

1. 生成语音需要应用内已保存的 Minimax API Key；模型可配置，缺省为 `speech-2.8-hd`。旧环境变量不参与生成，也不自动迁移。
2. API Key 在 Windows 当前用户范围内加密持久化，不以明文写入文件、回传到配置界面或记录到日志；前端只读取模型和是否已配置。配置损坏、解密失败、缺少凭证及外部请求/响应错误必须显式返回，不能用环境变量回退。
3. 文案不能为空且最多 2000 个 Unicode 字符；语速必须在 `0.5..2.0`，生成音量必须在 `0..1`。
4. 生成结果以 MP3 保存到 `Downloads/SmartAnnounce`，试听通过 Data URI 使用，导出使用保存对话框选择的目标。
5. 未生成音频时播放和导出必须失败并提示；取消保存对话框不是错误。
6. 已存在的导出目标必须显式失败，不能静默覆盖。
7. TTS 响应必须经过 HTTP 状态、业务状态、音频数据存在性和十六进制解码校验。
8. 成功生成的音频对应当次提交的文案、音色、生成参数和模型；后续编辑不改变已保存的音频。试听与导出仍作用于该文件，但界面必须明确标识它属于上一版本，不能冒充当前编辑内容的结果。
9. Minimax TTS 请求默认直连，不跟随系统或环境变量中的代理；仅在应用设置明确选择自定义代理时使用保存的 HTTP/HTTPS 主机和端口。代理 URL 不允许嵌入用户名密码；代理不可用时应报告原错误，不自动改走直连。已有配置缺少代理设置时视为直连，切换模式不得改变系统代理或丢失已保存的 Key/模型。
