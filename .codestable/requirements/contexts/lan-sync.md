# 局域网文件同步

面向无需 Git 操作、需要在两台经常离线的电脑间保持文档一致的用户。

## 通用语言

**设备身份**：首次运行生成并持久保留的身份凭证；IP 与端口只是设备当前的连接地址。

**同步目录对**：两台已配对设备分别批准的一对本地目录，是独立的同步、暂停和历史查看范围。

**共同版本**：双方确认一致的上一次内容，是判断单端修改、双端修改与离线冲突的基准，不是最近一次扫描时间。

**历史版本**：接收覆盖、删除或恢复之前，在受影响电脑上保存的原内容；与用于合并的共同版本分开管理。

**冲突副本**：双方修改无法自动合并时，以稳定名称保留的另一份完整内容；不是同步失败，也不要求立即二选一。

## 稳定规则

- 先双端确认配对，再由本机确认开放哪个目录；配对不授予任意磁盘浏览权限。
- 设备离开网络是正常状态。重新出现时按身份验证并更新地址，不因 IP 或端口变化而重配对。
- 默认双向，支持多个目录对；文件内容相同则不传输、不重复备份。修改时间不能单独成为丢弃内容的依据。
- 单端修改自动传播；双端 Markdown 修改以共同版本尝试行级合并。仅支持 UTF-8 且每个版本不超过 2 MiB；不支持或有冲突时保留双方内容。其他文件不提供内容差异界面。
- 冲突保留不阻塞其他文件。主文件选择只确定命名，不宣称该版本在语义上更正确；用户可以保留两份或在 Markdown 差异工作区明确保存合并。
- 保存人工合并前必须再次校验所查看版本；过期决策不能覆盖后续修改。
- 覆盖和确认删除前，受影响端先备份自己的旧版本。备份失败、内容校验失败或写前版本变化时不得覆盖；中断与部分成功不得伪报两端已一致。
- 删除默认不传播、不自动补回；确认后才删除两端。移除同步只解除配置，不删除资料或历史版本。
- Git 仓库中的忽略规则参与双方路径保护，已跟踪文件不因命中忽略项而被跳过；Git 元数据不参与同步。
- 同步目录之间不得重叠，也不得与应用数据或备份目录重叠。备份不自动清理；更改位置不使旧位置的版本失去可追溯性。
- 离线时展示等待连接及上次完成时间，不将未知远端状态表述为当前已一致。关闭窗口继续托盘运行，退出后停止同步。
