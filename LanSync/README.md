# 局域同步 · LanSync

独立的 Go + Wails + React 桌面应用，让两台局域网电脑上的多对目录保持一致。首版以 Windows 为目标，不需要 Git 操作、账号或云端服务。

## 开始使用

1. 两台电脑分别运行 `LanSync.exe`。在设置中按需点击「允许局域网连接」，确认 Windows 授权；规则仅作用于本应用、专用网络和本地子网。
2. 打开「设备」，选择附近设备。无法发现时，在「连接信息」查看本机地址，由另一台输入 `IP:端口`。
3. 核对两端配对码，并分别确认。
4. 一端点击「添加目录」，选择本机文件夹并发送邀请；另一端选择自己的对应文件夹。
5. 点击「预览并开始」。可以继续添加其他目录对。

关闭窗口会进入系统托盘，仍继续同步。真正退出请使用托盘菜单或设置中的「退出应用」。开机启动默认关闭，可在设置中开启。

## 同步行为

- 默认双向，自动监听文件变化，并每分钟补充完整内容核对；也可以手动立即同步。
- 使用 SHA-256 判断内容。相同文件不传输、不生成重复备份；修改时间只参与冲突主文件的选择。
- 保存上次共同版本。离线期间可以分别编辑，重连后按共同版本核对，不要求固定 IP 或端口。
- UTF-8 Markdown（`.md`，每个版本不超过 2 MiB）尝试行级三方合并。不重叠修改自动合并；无法合并则保留双方版本。
- 冲突副本以设备身份和内容摘要稳定命名，不弹窗、不阻塞其他文件。Markdown 可以查看差异、逐处选择、编辑结果并保存；其他文件不显示内容差异。
- 删除不自动传播，也不自动补回。对应记录中明确确认后，备份仍存在的版本，再删除两端文件。
- Git 仓库中遵循根级和嵌套 `.gitignore`、`info/exclude` 与配置中的 `core.excludesfile`，已跟踪文件不因命中忽略项而被跳过。支持嵌套仓库和工作树的公共排除项；不依赖本机 Git 命令。
- `.git` 元数据不传输。任一端排除的路径不自动写入，目录详情可查看跳过记录。未检测到 Git 仓库时，不单独启用 `.gitignore`。

自动合并只保证文本编辑不重叠，不保证语义没有矛盾；原版本仍可恢复。

## 备份与恢复

默认备份位置为 `%AppData%\LanSync\backups`，可以在设置中更改。每台电脑独立保留自己即将被覆盖或删除的旧内容。

- 备份目录不能与同步目录重叠；同步目录之间也不能重叠。
- 备份失败、文件被占用、文件再次变化或接收内容校验失败时，不覆盖原文件。
- 历史版本支持「恢复到文件夹」与「恢复并同步」。恢复后的新修改仍遵循正常冲突规则。
- 更改备份位置不会搬迁旧版本，恢复旧版本仍需原备份位置可用。
- 不自动清理备份；空间不足会明确报错并停止受影响文件的覆盖。

应用配置、设备身份、共同版本与历史索引保存在 `%AppData%\LanSync`。不要把一台电脑的整个应用数据目录复制给另一台电脑，也不要手动修改数据库或设备密钥。

## 安全与适用范围

配对连接使用 TLS 1.3 和持久设备证书指纹；未配对设备不能读取同步目录，已配对设备也只能访问经本机确认的目录。地址变化后的重新发现仍须通过身份校验。局域网广播不公布文件名或目录内容。

首版同步普通文件，不复制空目录、符号链接、ACL 或扩展属性。文件重命名按新增与删除处理。不提供运行中数据库、虚拟机或多文件业务的一致性快照；两端文件替换不是分布式原子事务，中断后会重新核对。

应用保留 `.lansync-` 临时文件命名空间，重启时只清理其中带合法随机标识的普通传输临时文件。请不要把自己的资料命名为该前缀。

自动发现目前使用 IPv4 mDNS；访客网络、AP 隔离或企业策略可能阻止互连。未在同一可互通局域网时等待重连，不做公网穿透或关闭系统防火墙。

## 开发与构建

环境：Go 1.26、Node.js 24、Wails CLI 2.11、Windows WebView2 Runtime。

在 `LanSync/` 中运行：

```powershell
npm --prefix frontend ci
npm --prefix frontend run build
go test ./...
npm --prefix frontend test
wails build -clean
```

输出：`build/bin/LanSync.exe`。开发启动使用 `wails dev`。竞态检查使用 `go test -race ./...`，Windows 上需要可用的 C 编译器。

隔离调试可指定独立数据目录和回环监听：

```powershell
.\build\bin\LanSync.exe --data-dir E:\LanSync-Test-A --listen 127.0.0.1:49731 --no-discovery
```

同一数据目录使用单实例窗口锁。不同测试实例必须使用不同数据目录和端口。

## 验证边界

自动化测试覆盖真实 TLS 两端通信、双端确认、换端口重连、共同版本恢复、多目录并行、后台监听、备份恢复、删除确认、Markdown 合并与过期决策保护、Git 排除及路径保护。Wails 开发界面已连接两个真实后端实例，完成配对、目录关联、600 个文件同步和 Markdown 差异操作。

当前 Windows 权限不允许创建符号链接，对应动态测试被跳过，仍待具备权限的环境验证。真实双机的广播发现、防火墙 UAC、开机启动和休眠唤醒也待实机验证。独立数据安全审查尚未完成；用于重要资料前，应先完成这两项验证，并保留独立备份。
